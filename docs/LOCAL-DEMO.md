## 1. 这套本地版做了什么

| 页面 | 业务 | 对应纪要痛点 |
|---|---|---|
| 资料库流水线 | 收件箱 → 识别 → 字段映射 → 清洗 → 与底账核对 → 四件套 → 台账 | 表头不统一、重复填报、人工核对 |
| 数据工作台 | 学生主档、学院/状态/异动、数据质量、UID/脱敏、四件套下载 | 数据分散、统计靠人工、敏感字段 |
| 报表中心 | 模板 + 字段勾选 + 筛选 + CSV 导出 + 导出记录 | 各部门反复要表、格式混乱 |
| 学籍异动 | 发起异动 → 待教务确认 → 状态联动 → 异动台账 | 流失率人工统计、状态不一致 |
| 辅导员工作台 | 只显示所带班级、本班待办、导出本班名单 | 辅导员权限与数据范围 |
| 学生自助填报 | 学生补联系方式/家长信息 → 辅导员审核 → 完整度提升 | 问卷星收集、手工抄录 |
| AI 问数 | 本地规则问数：学院/状态/质量/异动/报表引导，范围与审计 | 数据安全、AI 顾虑 |
| 学生信息 / 数据导入 | 原有主系统页面保留 | — |

### 演示故事线（约 5 分钟）

1. **资料库流水线**：点“开始整理收件箱”，5 份来源表依次完成识别/映射/清洗/核对/四件套/台账。
2. **数据工作台**：看 5,581 人的学院、学籍状态、异动和数据质量；点学生看 UID + 脱敏档案。
3. **报表中心**：选“学平险名单”或“退学名单”，导出 CSV（Excel 可打开），展示导出记录。
4. **学籍异动**：选一名学生发起休学 → 教务确认 → 学生状态更新为休学，操作记录留痕。
5. **辅导员工作台**：切换辅导员，只看到本班学生，导出本班名单。
6. **学生自助**：学生补电话/家长信息 → 辅导员审核 → 信息完整度从 1/3 变 3/3。
7. **AI 问数**：问“人工智能学院有多少学生”“全校休学和退学各有多少人”，展示本地规则、范围与问数记录；Dify 后续替换 planner。

## 2. UID、脱敏与映射

- 页面与导出使用 **UID**：`SK-<入学年份>-<6位流水>`，例如 `SK-2026-000123`。
- 页面不展示原始学号；姓名、身份证、电话默认掩码；家庭住址只保留到市/区。
- UID ↔ 原始学号/姓名/身份证/电话的映射单独生成在：
  `Z:\ai\本地部署\demo-private\uid_map.private.csv`
- 映射文件**不进入仓库、不进入演示容器、不对外提供**。真实数据接入时，映射表必须离线加密保存并限定访问人。
- 数据生成脚本：`scripts/demo/build_demo_dataset.py`，可重新生成；源目录默认是 WorkBuddy 交付材料，可用 `--source` 指定。

重新生成：

```bash
python scripts/demo/build_demo_dataset.py \
  --source "C:/Users/luofeng/Desktop/思科职院AI试点交付材料" \
  --out web/public/demo \
  --private "Z:/ai/本地部署/demo-private"
```

生成物：

- `web/public/demo/demo-data.json`：页面数据（UID + 脱敏字段）
- `web/public/demo/four-sheet.xlsx`：标准化数据 / 异常清单 / 字段映射 / 核对汇总
- `Z:\ai\本地部署\demo-private\uid_map.private.csv`：私有映射（不提交）

## 3. 启动与停止

前置：主栈已启动，`campus-gateway` 正在运行（登录和 `/gw` 代理依赖它）。

```powershell
# 启动本地演示（构建本地前端镜像，8083，不改动 8082）
.\scripts\demo\start-local-demo.ps1

# 停止
.\scripts\demo\stop-local-demo.ps1
```

脚本会：

1. 检查 `campus-gateway` 是否运行；
2. 构建 `campus-data-web:local-demo`；
3. 在 `campus-net` 上启动 `campus-web-demo`，映射 `127.0.0.1:8083:80`；
4. 检查 `/healthz` 并打开浏览器。

主栈未启动时，先启动现有本地栈（或至少 `campus-gateway` / `gateway-db` / `gateway-redis` / `campus-web` 所在网络）。

## 5. 当前边界与已知限制

- **所有数据为虚构**；没有接真实学生信息。
- 异动、学生自助、导出记录目前是**前端本地状态 / 浏览器 localStorage**，刷新或换容器会重置；正式版必须落到后端与审计表。
- 资料库流水线是**用已生成数据模拟**；正式版需要接后端上传/解析/任务队列。
- 页面按桌面 1920 设计；移动端尚未做专门适配。
- AI 问数当前是**本地规则版**，不是 Dify/LLM；当前独立的只读 AI POC 不在这套演示入口内。
- 不包含正式库迁移、正式认证切换、TLS/域名、生产监控；这些仍按 `PRODUCTION-READINESS-REPORT.md` 的 C 类事项处理。

## 6. Dify / AI 的下一步

建议把 Dify 作为**旁路 AI 层**，不放进数据主链路：

- Dify 部署在另一台 4C8G+ 机器或本机（官方最低 2C4G、建议 4C8G、磁盘 50GB 起）；
- Dify 不持有业务库凭据，只调用平台 API（报表、聚合查询、异常解释）；
- 真实数据阶段只接本地/校内模型，明确存储位置、访问权限、留存周期和模型调用链；
- 先用虚构数据做“问数 / 生成名单 / 解释异常”三个工作流，再评估真实数据审批。
