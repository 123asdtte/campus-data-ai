# 本地演示版 · 学生数据工作台

- **状态**：本地演示，已构建并在 Docker 中验收
- **入口**：<http://127.0.0.1:8083>
- **数据**：WorkBuddy 校园试点交付材料中的**虚构数据**（5,581 名学生 / 135 个班 / 6 个学院）
- **边界**：不接真实学生数据、不写正式库、不上传云端；现有 `8082` 前端与主栈不受影响

> 演示数据，非真实人员信息。不得用于评奖、处分、注册、上报等真实业务。

## 2. 这套本地版做了什么

| 页面 / 角色 | 业务 | 对应痛点 |
|---|---|---|
| 我的课表（学生） | 学生本人周课表、今天/下午课程、课表问答 | 学生只查课，不能看别人 |
| 辅导员工作台（辅导员） | 登录绑定所带班级、本班待办、本班名单导出 | 辅导员数据范围 |
| 学籍异动（辅导员/学工处） | 登记/Excel 导入、平台核对、导出；正式审批仍在青果/线下 | 原始 Excel 台账统一管理 |
| 数据工作台（学工处/管理员） | 学生主档、学院/状态/异动、数据质量、UID/脱敏、四件套 | 数据分散、重复填表 |
| 资料库流水线（学工处/管理员） | 收件箱 → 识别 → 映射 → 清洗 → 核对 → 四件套 → 台账 | 表头不统一、人工核对 |
| 报表中心（学工处/管理员） | 模板 + 字段勾选 + 筛选 + CSV 导出 + 导出记录 | 各部门反复要表 |
| AI 问数（管理员） | 管理员全局聚合演示；学生 AI 在“我的课表”内，只答本人课表 | 数据安全、AI 权限 |

已隐藏/后置：学生自助填报为 P2（管理员可预览）；财务系统不做；青果/喜鹊儿仍是源系统，本平台不回写。

### 演示故事线（约 6 分钟）

1. **学生**：用 `SK-2026-000001` 登录 → 直接进入“我的课表”→ 问“今天下午有没有课” → 只返回本人课程。
2. **辅导员**：用 `counselor01` 登录 → 只看到本人班级/学生 → 打开本班异动，只有本班 6 条。
3. **学工处**：用 `xgb01` 登录 → 数据工作台看全校聚合 → 学籍异动导入 Excel → 平台核对 → 导出。
4. **管理员**：用 `admin` 登录 → 资料库流水线、报表中心、全局 AI 问数、四件套。

## 3. UID、脱敏与映射

- 页面与导出使用 **UID**：`SK-<入学年份>-<6位流水>`，例如 `SK-2026-000123`。
- 页面不展示原始学号；姓名、身份证、电话默认掩码；家庭住址只保留到市/区。
- UID ↔ 原始学号/姓名/身份证/电话的映射单独生成在：
  `Z:\ai\本地部署\demo-private\uid_map.private.csv`
- 映射文件**不进入仓库、不进入演示容器、不对外提供**。真实数据接入时，映射表必须离线加密保存并限定访问人。
- 数据生成脚本：`scripts/demo/build_demo_dataset.py`，可重新生成；源目录默认是 WorkBuddy 交付材料，可用 `--source` 指定。

## 4. 角色与权限的当前实现

- 登录：`/gw/auth/login`；登录后前端调用 `/gw/system/user/getInfo` 获取当前用户、角色和权限。
- 菜单：`AppLayout` 根据网关角色生成；学生只有“我的课表”，辅导员只有“辅导员台/学籍异动”，学工处为工作台/流水线/报表/异动/辅导员预览。
- 路由：`RequireRoles` 做二级守卫，直接输入未授权 URL 会回到该角色首页。
- 数据范围：
  - 学生课表按登录 UID 匹配本人班级；
  - 辅导员台和辅导员异动按登录昵称匹配所带班级；
  - 学工处/管理员看全校。
- **当前限制**：演示数据是静态 JSON，数据范围在页面层过滤；正式版必须把同样的范围规则下沉到 API（学生端不能下载全班/全校数据）。
- 正式版学生登录用“学号 + 初始密码”，服务端把学号映射到 UID；短信已停，重置由辅导员/学工处办理。

## 5. 课表数据

来源：`全校教学基础数据/08_排课表（2026-2027学年第一学期）.xlsx`

字段：`学年学期 / 校区 / 上课班级 / 课程名称 / 任课教师 / 职称 / 星期 / 节次 / 周次 / 教室 / 备注`。

- 生成时会用班级信息表把“班级简称”归一到学生班级；当前 1,362 条排课全部匹配。
- 演示固定为**第 8 周**；课表问答会按周次过滤（单/双周、起止周）。
- 作息时间（第 1–2 节几点到几点）不在排课表里，当前使用默认值并在页面标注“待教务处确认”；正式接入需教务处提供作息/校历。
- 学生课表只读；不显示成绩、联系方式、其他学生，也不能导出名单。
- 课表问答是本地规则版，不调用外部模型；正式版可由 Dify/本地模型替换 planner，但工具仍按 UID 查询。

## 6. 学工在线异动台账

- 入口：`学籍异动`（辅导员、学工处、管理员）。
- 支持：手工发起、Excel/CSV 导入、平台核对、筛选、导出。
- 模板：`web/public/demo/change-import-template.csv`，列为
  `UID / 异动编号 / 异动类型 / 异动日期 / 异动原因 / 异动后去向 / 正式审批状态 / 备注`。
- 演示模板使用 UID；正式版导入 Excel 时由后端把学号映射为 UID，并按角色校验班级范围。
- “正式审批（源表）”与“平台核对”分开：平台核对**不修改**正式审批，也不回写青果；正式审批仍在青果/线下完成。
- 当前导入/核对状态保存在浏览器内存，刷新即重置；正式版必须落到后端并写审计。

## 7. 启动与停止

前置：主栈已启动，`campus-gateway` 正在运行（登录和 `/gw` 代理依赖它）。

```powershell
# 启动本地演示（构建本地前端镜像，8083，不改动 8082）
.\scripts\demo\start-local-demo.ps1

# 停止
.\scripts\demo\stop-local-demo.ps1
```

```powershell
python scripts/demo/smoke-demo.py
```

## 9. 当前边界与已知限制

- **所有数据为虚构**；没有接真实学生信息。
- 登录页“记住账号”只把用户名保存在本机 localStorage，不保存密码；公共设备请取消勾选。
- 学生/辅导员/学工处的**身份与菜单**由网关角色绑定；但演示数据是静态 JSON，**数据范围只在页面过滤**；正式版必须由 API 服务端强制过滤，学生端不能下载全班/全校数据。
- 异动、学生自助、导出记录目前是**前端本地状态 / 浏览器 localStorage**，刷新或换容器会重置；正式版必须落到后端与审计表。
- 资料库流水线是**用已生成数据模拟**；正式版需要接后端上传/解析/任务队列。
- 业务页面按桌面 1920 设计；登录页已适配移动端，其余页面尚未专门适配。
- AI 问数当前是**本地规则版**，不是 Dify/LLM；当前独立的只读 AI POC 不在这套演示入口内。
- 不包含正式库迁移、正式认证切换、TLS/域名、生产监控；这些仍按 `PRODUCTION-READINESS-REPORT.md` 的 C 类事项处理。

## 10. Dify / AI 的下一步

建议把 Dify 作为**旁路 AI 层**，不放进数据主链路：

- Dify 部署在另一台 4C8G+ 机器或本机（官方最低 2C4G、建议 4C8G、磁盘 50GB 起）；
- Dify 不持有业务库凭据，只调用平台 API（课表、报表、聚合查询、异常解释）；
- 学生 AI 只通过 UID 工具查本人课表；员工 AI 只按角色/部门范围查聚合；
- 真实数据阶段只接本地/校内模型，明确存储位置、访问权限、留存周期和模型调用链。
