## 2. 这套本地版做了什么

| 页面 / 角色 | 业务 | 对应痛点 |
|---|---|---|
| 我的课表（学生） | 学生本人周课表、今天/下午课程、课表与本人学籍档案问答 | 学生只查课，不能看别人 |
| 辅导员工作台（辅导员） | 登录绑定所带班级、本班待办、本班名单导出 | 辅导员数据范围 |
| 学籍异动（辅导员/学工处） | 登记/Excel 导入、平台核对、导出；正式审批仍在青果/线下 | 原始 Excel 台账统一管理 |
| 数据工作台（学工处/管理员） | 学生主档、学院/状态/异动、数据质量、UID/脱敏、四件套 | 数据分散、重复填表 |
| 资料库流水线（学工处/管理员） | 收件箱 → 识别 → 映射 → 清洗 → 核对 → 四件套 → 台账 | 表头不统一、人工核对 |
| 报表中心（学工处/管理员） | 模板 + 字段勾选 + 筛选 + CSV 导出 + 导出记录 | 各部门反复要表 |
| 悬浮 AI 助手（全角色） | 右下角统一入口，按当前页面与登录身份回答，气泡内标注该条回答的数据范围；学生只答本人课表与本人档案，可点课程卡定位到课表 | 减少页面跳转、AI 权限 |
| AI 问数（管理员） | 管理员全局聚合演示；学生使用悬浮助手，只答本人课表 | 数据安全、AI 权限 |

已隐藏/后置：学生自助填报为 P2（管理员可预览）；财务系统不做；青果/喜鹊儿仍是源系统，本平台不回写。

### 演示故事线（约 6 分钟）

1. **学生**：用 `SK-2026-000001` 登录 → 直接进入“我的课表”→ 问“今天下午有没有课” → 只返回本人课程。
2. **辅导员**：用 `counselor01` 登录 → 只看到本人班级/学生 → 打开本班异动，只有本班 6 条。
3. **学工处**：用 `xgb01` 登录 → 数据工作台看全校聚合 → 学籍异动导入 Excel → 平台核对 → 导出。
4. **管理员**：用 `admin` 登录 → 资料库流水线、报表中心、全局 AI 问数、四件套。

## 3. UID、脱敏与映射

- 页面与导出使用 **UID**：`SK-<入学年份>-<6位流水>`，例如 `SK-2026-000123`。
- 页面不展示原始学号；姓名、身份证、电话默认掩码；家庭住址只保留到市/区。
- UID ↔ 原始学号/姓名/身份证/电话的映射单独生成在：
  `Z:\ai\本地部署\demo-private\uid_map.private.csv`
- 映射文件**不进入仓库、不进入演示容器、不对外提供**。真实数据接入时，映射表必须离线加密保存并限定访问人。
- 数据生成脚本：`scripts/demo/build_demo_dataset.py`，可重新生成；源目录默认是 WorkBuddy 交付材料，可用 `--source` 指定。

## 4. 角色与权限的当前实现

- 登录：`/gw/auth/login`；登录后前端调用 `/gw/system/user/getInfo` 获取当前用户、角色和权限。
- 菜单：`AppLayout` 根据网关角色生成；学生只有“我的课表”，辅导员只有“辅导员台/学籍异动”，学工处为工作台/流水线/报表/异动/辅导员预览。
- 路由：`RequireRoles` 做二级守卫，直接输入未授权 URL 会回到该角色首页。
- 数据范围由 `demo-api` 在服务端按网关 token 身份判定：
  - 学生只返回本人档案、本人班级课表和本人异动；
  - 辅导员只返回所带班级/学生/异动；
  - 学工处/管理员返回全校。
- 完整演示数据和四件套已移出 `web/public`，旧公开地址返回 404；`/demo-api/data` 必须携带登录 token，四件套下载仅学工处/管理员可用。
- 正式版仍需把内存过滤替换为数据库行级权限、审计与分页查询。
- 正式版学生登录用“学号 + 初始密码”，服务端把学号映射到 UID；短信已停，重置由辅导员/学工处办理。

## 5. 课表数据

来源：`全校教学基础数据/08_排课表（2026-2027学年第一学期）.xlsx`

字段：`学年学期 / 校区 / 上课班级 / 课程名称 / 任课教师 / 职称 / 星期 / 节次 / 周次 / 教室 / 备注`。

- 生成时会用班级信息表把“班级简称”归一到学生班级；当前 1,362 条排课全部匹配。
- 演示固定为**第 8 周**；课表问答会按周次过滤（单/双周、起止周）。
- 作息时间（第 1–2 节几点到几点）不在排课表里，当前使用默认值并在页面标注“待教务处确认”；正式接入需教务处提供作息/校历。
- 学生课表只读；不显示成绩、联系方式、其他学生，也不能导出名单。
- 课表问答是本地规则版，不调用外部模型；正式版可由 Dify/本地模型替换 planner，但工具仍按 UID 查询。

## 6. 学工在线异动台账

- 入口：`学籍异动`（辅导员、学工处、管理员）。
- 支持：手工发起、Excel/CSV 导入、平台核对、筛选、导出。

  `UID / 异动编号 / 异动类型 / 异动日期 / 异动原因 / 异动后去向 / 正式审批状态 / 备注`。

- 发起、导入、核对已写入服务端 JSON 台账，刷新页面或重建容器后仍在；正式版必须改为数据库 API、行级权限与审计。

## 7. 启动与停止

前置：主栈已启动，`campus-gateway` 正在运行（登录和 `/gw` 代理依赖它）。

```powershell
# 启动本地演示（Compose 构建前端与 demo-api，监听 127.0.0.1:8083，不改动 8082）
.\scripts\demo\start-local-demo.ps1

# 停止
.\scripts\demo\stop-local-demo.ps1

# 仅清空演示异动台账（每次演示前可选；需显式 -Force；会短暂停止 demo-api 并先备份当前台账）
.\scripts\demo\reset-ledger.ps1 -Force

# 备份台账（默认写到 demo-api/state/backups/ledger-时间戳.json）
.\scripts\demo\backup-ledger.ps1

# 恢复台账（恢复前自动备份当前台账；demo-api 运行时会短暂停止后自动启动）
.\scripts\demo\restore-ledger.ps1 -File .\demo-api\state\backups\ledger-20261024-040000.json

# 一键校验（需栈已启动：healthz → 冒烟 → demo-api 单测 → Playwright E2E）
.\scripts\demo\verify-local-demo.ps1

# 只跑冒烟与单测，跳过 E2E
.\scripts\demo\verify-local-demo.ps1 -SkipE2E
```

脚本会检查网关，移除以 `docker run` 创建的同名旧容器，再用
`docker compose -p campus-demo -f docker-compose.demo.yml up -d --build`
启动两个服务，并等待 Web 健康检查通过。`demo-api` 通过服务名在 `campus-net`
内被 Nginx 解析，无需手工维护网络别名。

试用机需要非回环监听时，显式指定绑定地址与端口（须同时配置安全组/IP 白名单）：

```powershell
.\scripts\demo\start-local-demo.ps1 -Bind 0.0.0.0 -Port 8088
# 等价：$env:DEMO_BIND='0.0.0.0'; $env:DEMO_PORT='8088'; docker compose -p campus-demo -f docker-compose.demo.yml up -d --build
```

启动后跑只读冒烟（登录页、四角色身份、缺 token/伪 token/不存在账号拒绝）：

```powershell
python scripts/demo/smoke-demo.py
```

关键业务端到端回归（需演示栈已启动；测试前后会清空演示异动台账）：

```powershell
cd web
npm run test:e2e
```

demo-api 纯函数回归（身份范围、异动校验、台账合并；不启动服务、不写台账）：

```powershell
python -m unittest discover -s demo-api/tests -v
```

默认使用系统 Edge（`channel: msedge`）；CI 已安装 Chromium 时可设 `PW_CHANNEL=chromium`。

## 9. 当前边界与已知限制

- **所有数据为虚构**；没有接真实学生信息。
- 登录页“记住账号”只把用户名保存在本机 localStorage，不保存密码；公共设备请取消勾选。
- 筛选与输入控件均提供 `aria-label` 或可见标签关联（23 项 E2E 实测）：搜索框、学院/班级/状态/类型下拉、停用记录开关、AI 提问框、学生课表提问框、批次号输入。
- 学生/辅导员/学工处的身份与菜单由网关角色绑定；演示数据已由 `demo-api` 在服务端按 token 过滤。数据查询为内存只读，学籍异动为**受限写入**（JSON 台账），不做分页、数据库事务或独立审计表；正式版必须改为数据库 API + 行级权限 + 审计。
- 辅导员的带生范围只认登录账号（`userName`）经 `COUNSELOR_LABELS` 解析出的姓名标签，**不再看昵称**：网关的 `PUT /system/user/profile` 允许本人改昵称，若按昵称定范围，改个名字就能看到别的辅导员的学生。新增辅导员演示账号必须同时补这层映射，否则该账号看到的是空列表（默认拒绝）。正式环境应由数据库里的师生绑定关系决定，并建议同时收紧“本人可改昵称”的策略。
- 异动登记与平台核对已写入 `demo-api` 的 JSON 台账（`demo-api/state/ledger.json`，容器外持久化），但仍是**单文件演示存储**：无数据库事务、分页、并发审计；正式版必须落到数据库与审计表。文件不存在即空台账；文件被写坏（截断、非法 JSON、结构不对）时服务端**拒绝写入并返回 503**，同时把原件复制成 `state/ledger.corrupt-时间戳.json` 留作人工恢复，展示链路则退回基础演示数据不至于整站不可用。重置台账请用 `scripts/demo/reset-ledger.ps1 -Force`（会先停 `demo-api` 并备份当前台账），不要手工删文件。
- 学生自助、报表导出记录目前仍是**前端本地状态 / 浏览器 localStorage**；正式版必须落到后端与审计表。
- E2E 依赖已启动的 8083 演示栈与本机 Edge/Chromium；CI 的 `demo-e2e` job 用 Chromium 在全栈上跑同一批用例。测试会清空演示异动台账（仅限演示环境），CI 用命名卷隔离台账。
- CI：`.github/workflows/ci.yml` 的 `demo-tests` job（compileall + unittest）已在 PR #58 实跑通过；同次检查全部 success。`demo-e2e` job 首次实跑（commit 5af7220）为 10 passed / 1 failed（未启动业务库与导入服务、台账属主为容器 root）；修复后 run 40077110109（commit 8d9d525）**演示栈 E2E success**，与其余 7 个 job 一起全绿。E2E 已接入 CI。
- 资料库流水线是**用已生成数据模拟**；正式版需要接后端上传/解析/任务队列。
- 业务页面按桌面 1920 设计；`<=900px` 已改为顶部横向导航 + 满宽内容列（2026-10-24 修复内容列塌陷，E2E 断言内容列 ≥360px），但仍未做平板/手机的排版级精修。
- AI 问数与悬浮助手当前是**服务端规则版**（独立问数页也已走同一接口，前端不再自建规则），不是 Dify/LLM；`POST /demo-api/assistant/query` 用登录 token 调网关取身份，再由 `scoped_payload` 限定数据范围，前端不传 UID/角色。当前独立的只读 AI POC 不在这套演示入口内。
- 源表存在 1–7 数字星期；`demo-api` 加载时、前端展示时和数据生成器均已归一化为中文星期，避免 119 条排课在课表与问答中“消失”。
- 不包含正式库迁移、正式认证切换、TLS/域名、生产监控；这些仍按 `PRODUCTION-READINESS-REPORT.md` 的 C 类事项处理。

## 10. Dify / AI 的下一步

建议把 Dify 作为**旁路 AI 层**，不放进数据主链路：

- Dify 部署在另一台 4C8G+ 机器或本机（官方最低 2C4G、建议 4C8G、磁盘 50GB 起）；
- Dify 不持有业务库凭据，只调用平台 API（课表、报表、聚合查询、异常解释）；
- 学生 AI 只通过 UID 工具查本人课表；员工 AI 只按角色/部门范围查聚合；
- 真实数据阶段只接本地/校内模型，明确存储位置、访问权限、留存周期和模型调用链。
