# 执行协议（EXECUTION PROTOCOL）

- **版本**：v1.1（2026-10-22 修订：PR 范围界定、串并行规则、阶段回退、计数口径）
- **地位**：所有后续开发任务的统一工作方式。与 `PROJECT-ROADMAP.md`（做什么）配套，本文规定**怎么做、何时停、留什么证据**。

---

## 1. 两种任务模式

| 模式 | 触发 | AI 行为 |
|---|---|---|
| **总规划任务** | 启动新阶段 / 路线调整 | 先产出方案（目标/范围/验收/回退），经批准后**连续执行**，不再逐步请示 |
| **最终评审任务** | 一组相关工作完成 | 集中交付：PR + 测试证据表 + 回退 + 未覆盖项 + 风险，等人工复核 |

普通开发步骤（写代码、修测试、改文档）在这两种模式之间**自主完成**，不逐项请示。

---

## 2. 每个 PR 的固定流程

```
分支 feat/<主题>（从最新 main）
 → 实现（逻辑边界内可多 commit）
 → 自检矩阵：
    a. python -m pytest                 （关闭态全量，必须 0 failed）
    b. INTERNAL_AUTH_ENABLED=true pytest tests/<安全用例>（涉及时）
    c. 涉 SQL：scripts/init-test-db.py --force --verify（全新库演练）
    d. 涉前端/网关：对应构建 + 端到端探针
 → 作者自查（对照 PR 模板清单：认证/权限/范围/副作用/回退）
 → 更新证据表 + 行为矩阵 + 未覆盖项
 → push + PR（不自行合并）
 → 用户复核 → 合并
 → 合并后动作（按阶段矩阵：是否重建容器、是否执行迁移）
```

**测试失败处理**：先定位根因 → 区分"产品缺陷"（修代码）与"测试缺陷"（修断言并说明）→ 重跑全量。禁止删断言/放宽权限/伪造身份换绿。

---

## 3. 提交与分支规范

| 项 | 规则 |
|---|---|
| 分支 | `feat/<主题>`、`fix/<主题>`、`docs/<主题>`（统一 feat/，废弃 feature/） |
| commit | `type(scope): 中文主题`，正文列要点；type ∈ feat/fix/docs/test/ci/refactor |
| PR | 单 PR 对应一个阶段或明确边界；描述必含：改动清单、测试结果表、回退方式、未覆盖项 |
| main | 只接受 PR 合并；禁止直推 |
| 合并 | 仅用户批准后执行；记录 merge SHA |

---

## 3.5 PR 范围界定（一个 PR 只做一类事）

| PR 类型 | 允许改动 | 禁止混入 |
|---|---|---|
| 文档治理（G） | `docs/` 移动与更新、根 README/CONTRIBUTING | 任何业务代码、compose、SQL |
| 风险处置（R） | Appsmith 服务/数据源/只读账号、相关 compose 段 | 业务代码、认证开关 |
| 业务 PR（B/C/D/E） | 本阶段业务代码 + 对应测试 + 对应 SQL | 文档大规模治理、无关阶段的重构 |

同一 PR 里出现"顺手改的别的东西"= 范围违规，评审直接打回。

## 4. 测试命令（权威）

```bash
# 管理连接初始化（001→003→004 + 权限校验，CI 必跑）
python scripts/init-test-db.py --admin-dsn <DSN> --app-password <pw> --verify

# 关闭态全量（现网行为回归）
python -m pytest

# 开启态安全专项
INTERNAL_AUTH_ENABLED=true INTERNAL_HMAC_SECRET=<32+> \
  python -m pytest tests/test_internal_auth.py tests/test_route_matrix.py \
                   tests/test_student_write.py tests/test_db_privileges.py
```

CI 中：管理 DSN 必填（缺失即失败）；业务测试必须以 `campus_app` 运行；任何 SQL 失败非零退出。

## 5. 每阶段交付义务

完成一个阶段必须更新：

1. `PROJECT-ROADMAP.md` §2 总览表：该阶段状态列（计划中/进行中/已合并 + merge SHA）；
2. `docs/README.md` 索引（新增文档收录、已完成方案移 archive）；
3. 该阶段的 plan 文档 → 移入 `docs/archive/` 并加"已实施，见 merge SHA"头注；
4. `docs/ARCHITECTURE-AND-SECURITY-PLAN.md` §3 边界清单的状态列；
5. PR 描述 = 交付物本身（评审不依赖聊天记录）。

---

## 5.5 串行 / 并行与阶段回退

- **串行**：G → R → PR-B → PR-C → PR-D → PR-E（依赖链见 `PROJECT-ROADMAP.md` §4）；
- **可并行**：R 与 PR-B（不同服务）；同事线（Issue #3/#8）与 PR-B（不得改同一 compose 段或 `sql/` 授权脚本）；
- **阶段回退规则**：某阶段验收不过 → 回到该阶段修复；同一阶段连续两次修复仍不过 → 回到**前一阶段**重新评估依赖（例：PR-C 反复不过，可能是 PR-B 的权限点/学院声明模型有缺陷）；涉及授权模型变更 → 回到 `INTERNAL-AUTH-SPEC.md` 修订并重新评审。

## 5.6 计数与证据口径

- 报告测试结果必须区分**断言通过数**与**脚本段落数**：打印式脚本（如 POC `test_slice.sh`）没有 PASS/FAIL 计数，"12 项"只能是段落数；
- 运行时计数（如 POC `test_import_security.sh` 的 48）需注明"运行时计数，静态不可复算"；
- **"测试全绿"不等于"代码审查通过"**：安全结论必须给出文件行号 + 复现命令 + 期望输出；
- 审计类指标必须写明统计范围、分母、判定规则（基线见 `ARCHITECTURE-AND-SECURITY-PLAN.md` §2.5），**不导出业务明细或学生个人信息**。

## 6. 自主执行 vs 需要批准

### 可自主执行（计划范围内连续做）
- 代码实现、测试编写与修复、文档更新；
- 测试库/隔离环境的建库、迁移演练、重建容器（**开关保持关闭**）；
- PR 创建与推送；Issue 评论；依赖安装。

### 必须获得批准（不可自动）
- 合并任何 PR（含文档 PR）；
- 对**正式库**执行任何 SQL（含 004/005/006）；
- 开启 `INTERNAL_AUTH_ENABLED` 或修改正式 compose 的开关/密钥；
- 切换正式入口（关 8010、改 nginx 上游）；
- 扩大授权（新增角色/权限点/跨学院名单）；
- 采用第三方组件为生产依赖（如 plus-ui，许可未决）；
- 删除数据库卷、业务数据、测试数据或验收证据；
- 接入真实学生数据（任何阶段都禁止，除非另行专项批准）。

### 必须暂停并汇报
- 发现影响数据安全的根本设计问题；
- 回退演练失败；
- 依赖的外部系统（GitHub/POC 仓库）不可达导致验证缺口；
- 需要越出已批准的文件范围。

---

## 7. 中断恢复

状态持久化在三处，恢复时按序读取：

1. `PROJECT-ROADMAP.md` §2 总览表 —— 当前阶段与各阶段状态（唯一事实源）；
2. 当前阶段的 plan/PR（GitHub Issue/PR 评论含逐次证据）；
3. 本机 `memory/` 日志（过程细节）。

恢复规则：以 §1 总览表为准重建任务清单；已完成且已合并的阶段**不重做**；未合并的分支先比对远程 head 与测试记录对应 SHA，不一致则补跑测试。

---

## 8. 评审标准（人工复核清单）

每个 PR 的复核者按此清单判断：

- [ ] 行为矩阵：开关关闭/开启两列是否都成立？
- [ ] 新增/修改路由是否都挂了 `identity` 且有对应权限点？
- [ ] 拒绝路径是否有副作用断言（DB 行数 + 文件数快照）？
- [ ] 审计操作人是否来自签名身份？
- [ ] 测试是否真的执行（有 CI/本地输出），且覆盖负向场景？
- [ ] 回退是否三层齐全（配置/代码/DDL）？
- [ ] 未覆盖项是否如实列出？
- [ ] 是否混入本 PR 范围外的"顺手改动"？
- [ ] 报告的测试数字是断言数还是段落数？是否注明了口径？
- [ ] 涉及审计/数据的结论是否给出统计范围与分母，且未导出业务明细？
