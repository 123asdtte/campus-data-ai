## 二、关键证据

### 2.1 多工作表识别（改造前失败的那份文件）

```text
status=uploaded  sheet=人工智能学院  header_row=3  rows=469
needs_sheet_choice=True
sheets=[('人工智能学院',3,3,469), ('康养护理学院',1,3,424), ('财经商贸学院',3,3,306)]
missing=[]
序号→未识别  学号→学号  姓名→姓名  性别→未识别  身份证号→未识别  本人电话→未识别  班级→班级
```

改造前同一文件：`status=failed`、`COLUMN_MAPPING_REQUIRED`、`缺少必需列：学号, 姓名`。

三个工作表得分相同（各命中 3 列、含 2 个必填字段），系统按数据行数选中最优表，同时置 `needs_sheet_choice=true` 要求确认，不静默决定。

### 2.2 行号偏移

```text
预览：header_row=4  __row=[5,6,7]
校验：2 valid / 1 invalid
异常：row_number=6, MISSING_REQUIRED, student_name
```

表头在第 4 行时，问题行号必须整体后移，否则会指向错误行。已修正并通过本用例验证。

### 2.3 手动映射优先级

指定 `{"学生学号":"student_no"}` 后：

```text
conflicts=['学号']        ← 原「学号」列被解除占用
学生学号 → 学号 (manual, matched)
preview: student_no = E2026001X
```

若手动指定后仍让旧列胜出，用户改了映射却不生效，属于静默错误；已改为手动优先。
