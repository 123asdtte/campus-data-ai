## 四、额外核查：代理环境变量来源（只读，未修改）

| 项 | 结论 |
|---|---|
| 来源 | `~/.docker/config.json` 中的 `proxies.default`：`httpProxy`/`httpsProxy` = `http://127.0.0.1:8080`，`noProxy` = `localhost,127.0.0.1` |
| 注入机制 | Docker CLI/Compose 在**创建容器时**把这些值写成环境变量 |
| 作用范围 | 实测 5 个容器（campus-web、campus-db、campus-import-api、campus-appsmith、diet-gateway）**全部**包含 4 个变量（`HTTP_PROXY`/`HTTPS_PROXY`/`http_proxy`/`https_proxy`） |
| 为什么失效 | 值里的 `127.0.0.1` 在容器内指向**容器自己**，而宿主 8080 是 mihomo 代理（PID 67572），容器内并没有 |
| 影响面 | ① 容器内访问 PyPI/npm 全部失败（此前现象的真正原因）；② busybox `wget` 不识别 `no_proxy`，导致健康检查误判 unhealthy；③ **nginx 的 `proxy_pass` 不受影响**（nginx 不读环境变量代理） |
| 处置 | 健康检查改用 `curl --noproxy '*'`；**未修改 Docker 全局代理、未清空变量、未重拉镜像** |
| 建议（未执行） | 若将来容器需要出网，可在 compose 中显式覆盖 `HTTP_PROXY=http://host.docker.internal:8080`，或移除 `~/.docker/config.json` 的 proxies 段（需评估对其它项目影响） |
