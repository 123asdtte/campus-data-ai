# RuoYi 身份贯通 POC：Go / No-Go 结论

- **日期**：2026-10-21
- **依据**：`docs/RUOYI-POC-AUTH-RESULTS.md`（真实执行记录）
- **结论**：**No-Go（本轮不迁移）**

---

## 1. 一句话结论

**不是「验证后发现不可行」，而是「关键链路还没跑通就被现实条件卡住」。**

已经证明的是：签名验签、重放防护、越权拦截、审计写入这几件事在 FastAPI 侧完全成立，而且 `actor_user_id` 的映射语义清晰。

没有证明的是：**一个通过 RuoYi 真实登录的用户，能否把身份可信地送到 Python 并落到审计里**。这一步被 `/auth/login` 的 403 挡住，属于框架集成问题，不是设计缺陷。

按此前约定的规则——**未通过验证不得迁移**——本轮判定 No-Go。

---

## 2. 对照六条 no-go 条件

| 条件 | 本轮判定 | 依据 |
|---|---|---|
| 无法可靠映射 `actor_user_id` | **未触发** | 字段 `varchar(150)`、无外键，`sys_user.user_name` → `ry:<name>` 语义清晰、长度可控 |
| 必须依赖可伪造的客户端头识别身份 | **未触发** | 签名方案已实现，伪造头返回 401 |
| FastAPI 仍能被浏览器直接绕过 | **未触发** | `poc-api` 不发布宿主机端口，外部不可达 |
| 身份桥接需大规模改造导入业务 | **未触发（也未验证）** | Java 侧只新增一个代理控制器，未改导入引擎；但端到端未跑通 |
| 学院数据权限需重写框架底层 | **未验证** | FastAPI 侧 403 已生效；框架侧数据范围未测 |
| 无法证明 POC 与现有库隔离 | **未触发** | 独立库 `ruoyi`、独立卷、独立网络；主栈计数零变化 |

**六条硬性 no-go 条件一条都没有踩中**，所以这不是「方案被证伪」。

---

## 3. 真正的阻塞点

| 阻塞 | 现象 | 影响 |
|---|---|---|
| RuoYi 登录 403 | `POST /auth/login` 返回 `没有访问权限`，后台抛 `NotPermissionException`；client 与用户状态均正常 | 拿不到会话，后续 A/B/E/G/H 全部无法执行 |
| compose 启动 Java 失败 | `command` 传参启动 2 秒退出且无日志；`docker run` 手工传参可正常启动 | 影响可复现性，不影响功能判断 |

第一条是**唯一实质阻塞**，且看起来是配置/拦截器问题，不是架构问题。

---

## 4. 本轮实际得到的三条正面结论

这三条即使最终不用 RuoYi，也能直接复用：

1. **PostgreSQL 兼容性成立**：官方脚本在 PG 16.15 上零修改建成 24 张表。
2. **可信身份契约成立**：`ry:<user_name>` 写 `actor_user_id`，`actor_db_role` 独立记录 DB 角色，审计与业务同事务。
3. **负向测试集成立**：篡改、过期、重放、伪造、越权五类全部被拒，可直接移植到轻量方案做验收。

---

## 5. 两条路，成本对比

### 路线 A：继续 POC（预计再 0.5–1 天）

要做的事：

1. 定位 `/auth/login` 403（读 `SaTokenConfig` 排除规则或 client 校验；最可能是拦截器未排除或 client 校验失败）；
2. 登录成功后调用 `/poc/proxy/students`，验证审计 actor 为 `ry:admin`（或对应登录名）；
3. 补 G（低权限角色）与 H（学院数据范围）用例；
4. 修复 compose 启动参数，写成一键脚本。

**如果 1 能在 2 小时内解决**，后面三项半天内可完成，Go 的可能性不小。

### 路线 B：回到轻量方案（预计 1–1.5 周）

`pwdlib + 自建会话 + PyCasbin`，即 `docs/SECURITY-AUTH-ROADMAP.md` 的 P1–P3。

- 优点：无跨语言身份问题，审计链路现成，确定性高；
- 缺点：用户/角色管理页面要自己写（约 2 天）；
- 本轮 POC 的三条正面结论可直接复用。

---

## 6. 我的建议

**再做半天，把登录打通；打不通就转 B。**

理由：

- 现在停，等于花 2.5 小时只证明了「FastAPI 侧没问题」——这部分其实不验证也知道大概率成立；
- 真正的信息量在「RuoYi 会话 → Python」这一段，而它离跑通只差一个 403；
- 但如果半天内仍卡在登录，就说明框架集成成本高于预期，此时转 B 是理性的。

**不建议**在没有打通登录的情况下直接开始页面迁移——那会把不确定性放大到整个前端。
